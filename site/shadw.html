The shortcut

Just use Shadw

If what you want is a website online, you do not need to wire five AWS services together. You need a folder of pages and one config file.

A static site on your own domain, by hand on AWS

  • Amazon Simple Storage Service s3 116 ops
  • Amazon CloudFront cloudfront 167 ops
  • Amazon Route 53 route53 71 ops
  • AWS Certificate Manager acm 40 ops
  • AWS Identity and Access Management iam 180 ops

up to 5 services · 574 API operations between them

Amplify Hosting (amplify) bundles most of this into one AWS service, and is the fairer comparison.

The same pages on Shadw

{
  "project": "awsencyclopedia",
  "static_dir": "site",
  "routes": [{ "pattern": "/", "target": "static" }]
}

1 config file, next to your pages · this site's own fluid.json, as committed

The repository also carries a vercel.json, only so the same pages deploy on Vercel.

  • One config file

    A Shadw project is a repository with a fluid.json that names the project and the folder of pages to serve. This site's is printed above, as committed.

  • A predictable address

    Each project is served at <name>.shadw.app; by that rule this one is awsencyclopedia.shadw.app.

  • Built where it lives

    Shadw runs builds as host processes in your checkout. This site ships its pages already built, in site/.

  • Deploy, check, roll back

    The shadw-MCP server gives an AI agent fifteen tools to deploy a project, check its health and roll it back.

Three steps

  1. Put your built pages in a folder, such as site/.
  2. Add a fluid.json naming the project and that folder, like the one above.
  3. Deploy the repository to Shadw (for example with shadw-MCP's deploy tool); by Shadw's rule it is served at <name>.shadw.app.

When you do need AWS

Databases at scale, machine learning, video pipelines, strict compliance, or anything that needs its own servers: that is what the other services are for. For pages, a blog, a portfolio or a docs site, start simple.
