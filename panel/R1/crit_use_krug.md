| Critic: Usability (Krug) | Don't Make Me Think (Steve Krug): five-second test, clear over clever, obvious starting point, self-evident clickables, search that meets expectations | Home reads as "a field guide to AWS", but the main button sends newcomers to the 436-item list rather than the 13 basics, and "Shadw" and "fluid.json" are never explained. The wall's 436 squares are `<i aria-hidden>` with native `title` tooltips only, so nothing appears on touch. The 13 outlined squares can't be clicked. The "one blue Shadw square" is not in the wall at all: it is only a chip in the caption. Searching services.html for "database" (the placeholder's own example) returns 2 results, and A–Z sorts by SDK id, not by the name shown. The 13 rows in the list are not linked. Prev/next and "N of 13" work. File names mix lower and upper case (ec2.html vs DynamoDB.html), so /dynamodb and /Lambda return 404. The path to Shadw is clear and not pushy, but the final off-site button gives no next step. | OBJECT | Items 1-8 below. They are small and mechanical: no redesign needed. |

1. **There is no Shadw square in the wall.** The caption shows a blue swatch, so a visitor looks for a blue square among the 436 and never finds one, because it only exists in the caption chip `.one`. Fix: in `build.py`, add the blue square as the last cell of `.wall` (after "AWS X-Ray"), as `<a class="sh" href="shadw.html" aria-label="Shadw: one file, fluid.json">`, styled like `.one i`. Keep the caption chip as its key.
2. **You can't tell what a square is, and the 13 basics are anonymous.** The wall is `aria-hidden`, labels exist only as `title` tooltips (nothing at all on touch: tapping an outlined square at 375 does nothing), and the outlined squares aren't links. Fix: render the 13 `.b` cells as `<a href="ec2.html" aria-label="EC2">` and so on, with a 44px hit area through a `::after` inset on touch. Change the legend line to "the 13 basics (tap one)". Add one visible line under the caption that updates on hover or focus: "Hover a square to see its name". Remove `aria-hidden` from the wall's link cells.
3. **The five-second test fails on "where do I start".** The primary CTA "See all 436" drops a newcomer into the hardest page. The 13 basics, which the copy itself calls "the 13 you meet first", are below the fold on both viewports. Fix: make the primary button "Start with the 13 basics" (start.html). Make "See all 436" the secondary button, and keep "Or use Shadw →" as a text link.
4. **"Shadw" and "fluid.json" are never defined on the home page.** The headline "Your website needs one file" and the chip "fluid.json one file on Shadw" assume the visitor already knows what Shadw is. Fix: add one clause to the lede: "…Then it tells you the shortcut: Shadw, a host that serves a repository from a single fluid.json file."
5. **Search doesn't keep the placeholder's promise.** The placeholder says "queue, database, S3…", yet "database" matches only DMS and RDS (missing DynamoDB, DocumentDB, Aurora DSQL and others), and "cdn" matches nothing (CloudFront). Fix: add category and synonym words to each `<li data-n>`, at least the 13 basics' categories (compute, storage, database, messaging, security, delivery/cdn) plus "database" for docdb, dsql, neptune, timestream, keyspaces, memorydb and dax. Or change the placeholder to "name or SDK id, e.g. S3, lambda".
6. **A–Z isn't alphabetical by what's on screen.** `site.js` sorts by the last token of `data-n` (the SDK id), so "AWS Certificate Manager" sits between "Account Access Runtime" and "Agent Registry", and "Amazon Relational Database Service" files under R. Fix: sort by the visible name with a leading "Amazon "/"AWS " stripped, use the same order for the no-JS default, and label the button "A–Z by name".
7. **The 13 basics are dead ends in the full list.** Searching "s3" finds the S3 row, but none of the 436 `<li>` contains a link, so the visitor can't reach s3.html from there. Fix: wrap `.s-name` in `<a href="s3.html">` for the 13, add a small "basic" tag, and show those 13 first when the query matches.
8. **Mixed-case URLs break typed and shared links.** The files are ec2/s3/lambda.html but DynamoDB, RDS, IAM, SNS, SQS, CloudFront, Beanstalk, ElastiCache, EFS and EBS.html, so with Vercel `cleanUrls` the paths /dynamodb, /Lambda and /cloudfront return 404. Fix: emit all 13 in lowercase (dynamodb.html, rds.html, iam.html, sns.html, sqs.html, cloudfront.html, beanstalk.html, elasticache.html, efs.html, ebs.html) and keep the capitalised names as redirect stubs, as lamda.html already does.
9. **The Shadw path ends with no next step.** "Go to Shadw →" (https://shadw.app) leaves the site without saying what the visitor will do there. Fix: above the button, add three numbered steps using only facts the evidence verifies: "1. Add a fluid.json naming your project and folder. 2. Push the repository. 3. It is served at <name>.shadw.app." Relabel the button "Go to shadw.app →". There are 4 Shadw links on the home page and one callout per service page, which is acceptable: no change needed for pushiness.
